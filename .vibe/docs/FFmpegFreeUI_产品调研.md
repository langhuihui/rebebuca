## 1. 项目概述

### 1.1 基本信息

- **项目名称**: FFmpegFreeUI (3FUI)
- **开发语言**: .NET 10 (纯 WinForm 框架)
- **UI框架**: SunnyUI + 自绘制暗黑风格界面
- **许可证**: MIT 开源许可
- **运行平台**: Windows (原生)、Linux/macOS (通过 Wine 兼容层)
- **项目状态**: 活跃开发中

### 1.2 产品简介

FFmpegFreeUI 是 Windows 上 FFmpeg 的专业交互外壳，旨在让普通人能够通过图形化界面接触到较为全面的通用参数来轻松压制和转换格式。它既适合轻度专业用户，也适合深度专业人士。

**核心理念**: 参数真正透明、纯净自由、批量处理

**开发动机**: 市面上现有工具要么参数不透明，要么限制多，要么批量功能弱。3FUI 是被"气出来"的项目，旨在满足压片党的实际需求。

## 3. 用户场景分析

### 3.1 核心用户画像

#### 3.1.1 专业压片党
**特征**:
- 有大量视频需要批量处理
- 对画质有较高要求
- 熟悉视频技术参数
- 需要可重复使用的预设方案
- 需要精确控制编码参数

**使用场景**:
- 压制组批量制作资源
- 视频创作者批量转码
- 媒体库规范化处理
- 多格式统一转换

#### 3.1.2 视频创作者
**特征**:
- 需要导出多种格式
- 需要控制文件大小
- 对画质有要求但不极致
- 希望流程高效

**使用场景**:
- 为不同平台导出视频
- 压缩视频文件便于分享
- 音视频格式转换
- 批量处理素材

#### 3.1.3 技术爱好者
**特征**:
- 喜欢折腾参数
- 追求最佳压缩比
- 愿意学习新技术
- 使用最新编码器

**使用场景**:
- 测试新的 AV1 编码
- 对比不同编码器效果
- 学习视频编码技术
- 优化个人视频库

#### 3.1.4 企业用户
**特征**:
- 需要批量处理大量视频
- 需要稳定的批量任务队列
- 可能需要远程调用
- 需要定制化参数

**使用场景**:
- 企业培训视频转码
- 产品演示视频压缩
- 多语言版本处理
- 归档视频格式统一

### 3.2 典型使用流程

```
1. 准备阶段
   ├─ 下载并安装 FFmpeg
   ├─ 放置 ffmpeg.exe 到 3FUI 目录或添加到环境变量
   └─ 启动 3FUI

2. 参数配置
   ├─ 选择视频编码器 (如 libx265)
   ├─ 设置质量值 (CRF=24)
   ├─ 选择预设 (preset=medium)
   ├─ 配置色彩参数
   ├─ 添加滤镜 (如降噪、锐化)
   └─ 保存为预设 (可选)

3. 添加任务
   ├─ 拖拽文件到编码队列
   ├─ (可选) 按 Ctrl/Shift/Alt 打开单独参数面板
   └─ 任务自动创建并使用当前设置的快照

4. 执行任务
   ├─ 开始编码
   ├─ 实时查看进度和剩余时间
   ├─ (可选) 暂停/恢复任务
   └─ 完成后查看输出文件

5. 批量处理 (高级)
   ├─ 添加多个任务到队列
   ├─ 可配置同时运行数量
   ├─ 可单独调整每个任务的参数
   └─ 统一监控所有任务进度
```

## 4. 产品定位

### 4.1 目标用户

**✅ 适合的人群**:
- 愿意折腾、追求质量的用户
- 强迫症用户 (需要精确控制参数)
- 专业工作者
- 压片佬/压制组

**❌ 不适合的人群**:
- 想要无脑全自动的用户
- 不想看字、不想学任何东西的用户
- 只要简单转一下格式的用户

### 4.2 市场定位

#### 4.2.1 同类产品对比

| 产品 | 定位 | 参数透明度 | 批量能力 | 预设策略 |
|-----|------|-----------|---------|---------|
| **FFmpegFreeUI** | 专业级压制转换 | ⭐⭐⭐⭐⭐ 完全透明 | ⭐⭐⭐⭐⭐ 无限制 | 不内置预设 |
| **HandBrake** | 常规专业级 | ⭐⭐⭐⭐ 透明 | ⭐⭐⭐⭐ 强大 | 内置丰富预设 |
| **ShanaEncoder** | 专业级压制 | ⭐⭐⭐⭐ 透明 | ⭐⭐⭐⭐ 强大 | 内置预设 |
| "丸菠刹" 等商业工具 | 大众向 | ⭐⭐⭐ 较透明 | ⭐⭐ 有限 | 内置私人预设 |

#### 4.2.2 差异化定位

**与 HandBrake/ShanaEncoder 的区别**:
- 3FUI 只使用 ffmpeg 来执行任务，不内置任何编解码器
- 性能始终保持在最新水平 (直接使用最新 ffmpeg)
- 不会向输出文件写入软件信息
- 不碰注册表、不收集数据、完全纯净

**与商业工具 ("丸菠刹") 的区别**:
- 完全免费，所有生产力功能不收费
- 参数完全透明，无"私人秘制配方"
- 批量任务无限制
- 开源可定制

#### 4.2.3 独特定位

**"市面上唯一一个完全不内置现成预设的外壳"**

这是 3FUI 最大的差异化特点。用户必须了解基本参数概念，但这也带来了:
- 完全的参数透明和控制权
- 强迫用户学习正确的视频技术知识
- 避免被错误的概念误导
- 更灵活的定制能力

## 5. 技术架构

### 5.1 技术栈

| 技术领域 | 使用技术 |
|---------|---------|
| **开发语言** | .NET 10 (VB.NET) |
| **UI框架** | WinForm + SunnyUI |
| **运行库** | .NET 10 Runtime |
| **构建方式** | ReadyToRun / SelfContained / SingleFile |
| **编码后端** | FFmpeg (外部调用) |
| **性能监控** | LibreHardwareMonitorLib |
| **跨平台** | Wine 兼容层 (Linux/macOS) |
| **插件系统** | 反射 + 特性 + 动态调用 |

### 5.2 架构特点

#### 5.2.1 外壳设计
- 不内置 FFmpeg，用户需要自行放置
- 通过环境变量或本地路径查找 ffmpeg.exe
- 支持直接使用最新版本的 FFmpeg

#### 5.2.2 任务管理
- 每个任务拥有独立的参数快照
- 命令行在开始任务时强制生成
- 支持更新快照数据、反向读取快照
- 无限制任务队列

#### 5.2.3 插件系统
```vb
# 插件接口示例
Public Shared Property HostCall_AddCustomWinformPanel As Action(Of String, Control)
Public Shared Property HostCall_AddMissionToQueueWithArgs As Action(Of String, String, String, String)
Public Shared Property HostCall_MediaStreamVisualSelector As Action(...)
```
- 使用反射机制，无需引用 3FUI
- 支持自定义 WinForm 和 WPF 界面
- 支持向编码队列添加任务
- 支持媒体流可视化选择器

#### 5.2.4 远程调用
- 监听指定 UDP 端口 (默认 10591)
- 支持局域网远程发任务
- 消息格式与启动参数相同
- 适合大规模编码集群部署

### 5.3 依赖库

| 依赖库 | 许可证 | 作用 |
|-------|--------|------|
| SunnyUI | GPL-3.0 | 界面主框架 |
| WindowsAPICodePack | 微软软件许可证 | 文件夹选择对话框 |
| LibreHardwareMonitorLib | MPL-2.0 | 性能监控 |

**特点**: 依赖极少，连 Json.NET 都没用，非常轻量。

## 7. 与 Rebebuca 的协同价值分析

### 7.1 Rebebuca 项目概况

**Rebebuca** 是一个现代化的桌面应用，基于 Node.js + Vue 3 构建，用于快速管理和执行各种命令与脚本。

**核心功能**:
- 🚀 快速启动 - 一键创建和运行配置
- ⚡ 实时输出 - 实时查看命令执行结果
- 📝 配置管理 - 支持工作目录、环境变量等高级配置
- 🕒 历史记录 - 自动保存运行历史
- 🎨 现代化 UI - 基于 Naive UI 的精美界面
- 💾 持久化存储 - 配置和历史数据自动保存
- 🖥️ 跨平台 - 支持 Windows、macOS 和 Linux
- 🖥️ 终端选择 - 可选择首选的系统终端执行外部命令

**技术栈**:
- 前端: Vue 3 + TypeScript + Naive UI + Pinia + Vite
- 后端: Node.js + Rust

### 7.2 功能互补性分析

#### 7.2.1 协同点 1: 命令执行管理

**FFmpegFreeUI 的需求**:
- 需要管理 FFmpeg 命令的执行
- 需要批量执行任务
- 需要监控命令输出和进度

**Rebebuca 的能力**:
- ✅ 专业的命令执行管理界面

- ✅ 工作目录和环境变量管理
- ✅ 运行历史记录

**协同价值**:
Rebebuca 可以作为 FFmpegFreeUI 的"命令执行后端"，提供更强大的命令管理能力。

#### 7.2.2 协同点 2: 远程任务调度

**FFmpegFreeUI 的能力**:

**Rebebuca 的能力**:

**协同价值**:

#### 7.2.3 协同点 3: 预设管理

**协同价值**:
Rebebuca 可以增强 FFmpegFreeUI 的预设管理能力，提供更友好的预设编辑和分享功能。

## 8. 结论与建议

### 8.1 总结

**FFmpegFreeUI 是一个定位清晰、功能强大的专业视频转码工具**:

#### 优势:
1. ✅ 参数完全透明，适合学习和专业使用
2. ✅ 批量处理能力强，适合大规模任务
3. ✅ 支持最新 FFmpeg，技术先进
4. ✅ 完全开源免费，无广告无限制
5. ✅ 插件系统和远程调用扩展性强

#### 限制:
1. ⚠️ 学习曲线较陡，不适合新手
2. ⚠️ 不内置预设，需要用户自行配置
3. ⚠️ 界面风格较专业化，大众化程度低
4. ⚠️ 原生只支持 Windows (Linux/macOS 需 Wine)

### 8.2 与 Rebebuca 的协同价值

#### 8.2.1 高度互补性

两个项目在多个维度上高度互补:
- **功能互补**: FFmpegFreeUI 擅长 FFmpeg 参数配置，Rebebuca 擅长命令执行管理
- **用户互补**: FFmpegFreeUI 服务视频专业用户，Rebebuca 服务开发者和命令行用户
- **技术互补**: FFmpegFreeUI 是 .NET WinForm，Rebebuca 是 Node.js + Vue，技术栈不同
- **定位互补**: FFmpegFreeUI 专注视频处理，Rebebuca 专注通用命令管理

#### 8.2.2 协同潜力

**短期协同机会**:
1. Rebebuca 作为 FFmpegFreeUI 的远程控制前端

3. Rebebuca 的终端功能用于查看 FFmpeg 输出

**中期协同机会**:
1. 开发 3FUI 插件，集成 Rebebuca 的命令管理能力
