## 三、任务清单

### 3.1 类型与数据 (按需补全)

- [ ] **preset 类型**：`src/ffmpeg/types/preset.ts` 已存在且与设计 3.3.1 基本一致；若设计有 `OutputConfig`、`NamingConfig` 等独立导出或 `createDefaultPreset()`，按设计补全。
- [ ] **command / 其它**：若 `commandBuilder` 或 `validationService` 需独立类型（如 `ValidationResult`），放在 `types/` 或对应 service 文件内，与 3.3、3.4 一致。

### 3.2 工具函数 (utils)

- [ ] **time.ts**：`src/ffmpeg/utils/time.ts` — 按 模块详细设计 §7.1 实现 `TimeUtils`：`timeToSeconds`、`secondsToTime`、`formatDuration`、`parseFFmpegTime`。
- [ ] **path.ts**：`src/ffmpeg/utils/path.ts` — 按 §7.2 实现 `PathUtils`：`normalizePath`、`escapeShellArg`、`escapeWindowsPath`、`generateOutputPath`、`applyCustomNamingPattern`、`isValidPath`、`getExtension`。路径实现需兼容 Tauri 环境（可参考项目现有 `@tauri-apps/api` 或 Node `path` 的用法）。
- [ ] **validators.ts**（可选）：若 `ValidationService` 将部分纯函数抽到 utils，则新增；否则仅在 `validationService` 内实现。

### 3.3 服务层 (services)

- [ ] **validationService.ts**：`src/ffmpeg/services/validationService.ts` — 按 模块详细设计 §3.4.2 实现 `ValidationService`：`validatePreset`、`validateVideoArgs`、`validateAudioArgs`、`validateFilterChain` 及所有 private 校验方法；导出 `ValidationResult` 接口及单例 `validationService`。
- [ ] **commandBuilder.ts**：`src/ffmpeg/services/commandBuilder.ts` — 按 §3.4.1 实现 `CommandBuilder`：`build`、`buildBatch`、`validateCommand`，以及 `buildVideoArgs`、`buildAudioArgs`、`buildVideoFilters`、`buildQualityArgs`、`buildStreamMap`、`addDecoderArgs`、`addTrimmingArgs`、`addMetadataArgs`、`parseCustomParams`、`generateOutputPath`、`applyCustomNamingPattern` 等；依赖 `ValidationService`、`utils/time`、`utils/path`；导出单例 `commandBuilder`。  
  - 注意：设计中的 `getSubtitleFilter`、`getColorManagementFilters`、`getTransformFilters`、`getDeinterlaceFilter`、`getDenoiseFilter` 等需与 `preset.filters` 及 `SubtitleFilter` 等类型对齐；`path` 在浏览器/Tauri 下若不可用 `require('path')`，改用 `@tauri-apps/api/path` 或现有项目 path 工具。

### 3.4 状态层 (stores)

- [ ] **ffmpegParams.ts**：`src/ffmpeg/stores/ffmpegParams.ts` — 按 模块详细设计 §3.2 实现 Pinia store：`currentPreset`、`inputFiles`、`outputFile`、`commandPreview`、`isGeneratingCommand`；方法 `addInputFiles`、`removeInputFile`、`updatePreset`、`resetPreset`、`applyPreset`、`updateCommandPreview`。  
  - `updateCommandPreview` 内部调用 `commandBuilder.build`（或 `buildBatch` 取第一条），需与 `CommandBuilder` 接口一致；输入/输出路径从 `inputFiles`、`outputFile` 及 `currentPreset.output` 推导。

### 3.5 单元测试

- [ ] **time.spec.ts**：`src/ffmpeg/__tests__/utils/time.spec.ts` — 覆盖 `timeToSeconds`、`secondsToTime`、`formatDuration`、`parseFFmpegTime`。
- [ ] **validators.spec.ts**（若存在 `utils/validators.ts`）：`src/ffmpeg/__tests__/utils/validators.spec.ts`。
- [ ] **validationService.spec.ts**：`src/ffmpeg/__tests__/services/validationService.spec.ts` — 覆盖 `validatePreset`、`validateVideoArgs`、`validateAudioArgs`、`validateFilterChain` 及主要校验分支。
- [ ] **commandBuilder.spec.ts**：`src/ffmpeg/__tests__/services/commandBuilder.spec.ts` — 按 模块详细设计 §10.1 示例：基本 H.264、scale、crop；并补充 `buildBatch`、`validateCommand`、常见 quality 模式的用例。

### 3.6 导出与集成

- [ ] **index / 模块导出**：在 `src/ffmpeg/` 或合适入口导出 `commandBuilder`、`validationService`、`useFFmpegParamsStore`、`TimeUtils`、`PathUtils` 等，便于 阶段 2、3 及现有 Rebebuca 调用。
- [ ] **与现有 Rebebuca 的兼容**：不破坏现有构建、类型与测试；若用到 Tauri/Rust，需与现有 `src-tauri`、`invoke` 约定一致（本阶段以 TS 逻辑为主，可不新增 Tauri 命令）。
