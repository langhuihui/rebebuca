## 一、审批意见

### 1.1 方案审批

**审批结果**: ✅ **有条件批准**

**审批理由**:

#### 符合产品战略的方面
1. **功能互补性强**: FFmpegFreeUI 的 FFmpeg 参数配置能力可以显著增强 Rebebuca 的视频处理能力,拓展用户群体
2. **技术可行性**: "渐进式功能融合"方案风险可控,可以逐步实施,不会影响现有产品稳定性
3. **市场机会**: 视频处理需求持续增长,结合两个项目的优势可以打造差异化的产品竞争力
4. **用户价值**: 可以同时服务开发者和视频专业用户,扩大用户基础

#### 需要满足的前提条件
1. **保持产品定位清晰**: Rebebuca 必须保持"通用命令管理工具"的核心定位,FFmpeg 功能只是其中一个重要模块
2. **确保用户体验一致**: 融合后的 UI/UX 必须符合 Rebebuca 现有设计语言,避免割裂感
3. **功能优先级明确**: 必须严格控制开发范围,优先实现核心价值功能
4. **分阶段验证**: 每个阶段必须进行用户验收,确保方向正确

## 二、产品定位与战略

### 2.1 产品定位

**Rebebuca 新定位**:
> 一个现代化的桌面应用,用于快速管理和执行各种命令与脚本,支持通用命令执行和专业化视频处理能力。

**核心价值主张**:
- 🚀 **通用性**: 支持任意命令和脚本的快速执行
- 🎬 **专业化**: 提供 FFmpeg 专业视频处理能力
- 🎨 **现代化**: 简洁美观的用户界面和流畅的交互体验
- 🌐 **跨平台**: Windows、macOS、Linux 全平台支持
- 🔄 **可扩展**: 插件化架构,支持功能扩展

### 2.2 战略目标

**短期目标 (3-6个月)**:
- 完成 FFmpeg 核心功能融合
- 支持基础的视频转码和参数配置
- 吸引第一批视频处理用户
- 验证产品市场需求

**中期目标 (6-12个月)**:
- 完善 FFmpeg 高级功能(滤镜、色彩管理等)
- 构建预设分享生态
- 实现与 FFmpegFreeUI 的互操作
- 确立在开发者+视频处理用户交叉领域的品牌认知

**长期目标 (12个月以上)**:
- 打造完整的视频处理工具链
- 支持分布式视频编码集群
- 建设活跃的开发者社区
- 成为跨领域工具产品的标杆

### 3.2 分阶段产品规划

#### **阶段 1: MVP 核心功能 (2-3周)**

**目标**: 实现基础的视频转码能力,验证市场需求

**核心功能**:
- [x] FFmpeg 参数生成器(基础)
  - 输出容器选择(MP4、MKV、AVI、MOV、WebM)
  - 视频编码器(H.264、H.265、VP9、AV1)
  - 音频编码器(AAC、MP3、FLAC、Opus)
  - 基础质量控制(CRF、码率)
  - 分辨率设置
- [x] 进度解析器
  - 实时提取 FFmpeg 输出
  - 显示进度条(0-100%)
  - 显示帧率、码率、速度等基本信息
- [x] 预设管理(基础)
  - 保存/加载预设
  - 预设列表管理
  - 预设导入/导出(JSON 格式)
- [x] 基础视频转码
  - 支持单文件转码
  - 输入文件拖拽
  - 输出路径配置

**验收标准**:
1. 用户可以通过图形界面配置基础 FFmpeg 参数
2. 成功执行视频转码任务
3. 实时显示转码进度
4. 预设可以正常保存和加载
5. UI/UX 符合 Rebebuca 设计规范

**用户价值**:
- ✅ 满足 80% 的基础视频转码需求
- ✅ 比纯命令行使用更友好
- ✅ 可以快速验证产品方向

**技术要求**:
- 参考 `FFmpegFreeUI/编码任务/预设管理.vb` 的参数生成逻辑
- 使用 TypeScript 重写,不依赖 .NET
- 集成到 Rebebuca 的任务管理系统

---

#### **阶段 2: 批量任务与高级参数 (3-4周)**

**目标**: 提升批量处理能力,满足专业用户需求

**核心功能**:
- [x] 批量任务队列
  - 多文件批量添加
  - 并发数量配置(1-5个任务同时运行)
  - 任务优先级设置
  - 任务暂停/恢复/停止
  - 任务快照机制
- [x] 高级质量控制
  - VBR/VBR HQ/CQP/CBR 模式
  - 编码预设(preset: ultrafast~veryslow)
  - 色深设置(8bit/10bit)
- [x] 常用视频滤镜
  - 画面缩放(scale)
  - 画面裁剪(crop)
  - 转逐行(yadif)
  - 转隔行(tinterlace)
  - 烧录字幕(ass/srt)
- [x] 硬件加速支持
  - NVIDIA NVENC (H.264/H.265/AV1)
  - Intel QSV (H.264/H.265)
  - AMD AMF (H.264/H.265)

**验收标准**:
1. 支持批量处理 100+ 个视频文件
2. 可以同时运行多个任务
3. 任务可以被暂停和恢复
4. 滤镜可以正确应用到视频
5. 硬件加速正常工作(NVIDIA/Intel/AMD)

**用户价值**:
- ✅ 满足专业用户的批量处理需求
- ✅ 显著提升工作效率
- ✅ 支持 95% 的常见视频处理场景

**技术要求**:
- 利用 Rebebuca 现有的任务队列能力
- 扩展任务管理器,支持 FFmpeg 特定的状态管理
- 参考 3FUI 的滤镜参数映射逻辑

## 五、与 Rebebuca 原有功能的整合策略

### 5.1 架构整合

#### 模块化设计

```
Rebebuca
├── 核心 Core
│   ├── 命令执行引擎
│   ├── 任务管理器
│   ├── 终端集成
│   └── 状态管理 (Pinia)
│
├── 通用模块 Common
│   ├── 配置管理
│   ├── 历史记录
│   ├── 设置管理
│   └── 文件操作
│
└── 专用模块 Specialized
    ├── FFmpeg 引擎 ← 新增
    │   ├── 参数生成器
    │   ├── 进度解析器
    │   ├── 预设管理
    │   └── 滤镜系统
    │
    └── 未来扩展...
```

**设计原则**:
1. **低耦合**: FFmpeg 模块独立,不影响核心功能
2. **高内聚**: FFmpeg 相关功能集中在一个模块
3. **可扩展**: 便于未来添加其他专用模块
4. **可测试**: 每个模块可以独立测试
