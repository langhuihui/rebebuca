## 一、项目概述

### 1.1 产品定位

Rebebuca 是一个现代化的桌面应用,用于快速管理和执行各种命令与脚本。通过融合 FFmpegFreeUI (3FUI) 的视频转码能力,Rebebuca 将扩展为支持通用命令执行和专业化视频处理能力的综合性工具。

**核心价值主张**:
- 🚀 **通用性**: 支持任意命令和脚本的快速执行
- 🎬 **专业化**: 提供 FFmpeg 专业视频处理能力
- 🎨 **现代化**: 简洁美观的用户界面和流畅的交互体验
- 🌐 **跨平台**: Windows、macOS、Linux 全平台支持
- 🔄 **可扩展**: 插件化架构,支持功能扩展

### 1.2 目标用户

| 用户类型 | 占比 | 核心需求 | 典型场景 |
|---------|------|---------|---------|
| **开发者+视频创作者** | 35% | 需要管理命令+视频处理 | 开发工具+视频制作 |
| **DevOps 工程师** | 25% | 批量视频转码、自动化脚本 | 企业视频归档、培训资料处理 |
| **技术爱好者** | 20% | 学习 FFmpeg、折腾参数 | 个人视频库优化、技术实验 |
| **视频专业工作者** | 20% | 专业视频压制、批量处理 | 压制组工作、媒体内容制作 |

### 1.3 产品目标

**短期目标 (3-6个月)**:
- 完成 FFmpeg 核心功能融合
- 支持基础的视频转码和参数配置
- 吸引第一批视频处理用户
- 验证产品市场需求

**中期目标 (6-12个月)**:
- 完善 FFmpeg 高级功能(滤镜、色彩管理等)
- 构建预设分享生态
- 实现与 FFmpegFreeUI 的互操作
- 确立在开发者+视频处理用户交叉领域的品牌认知

**长期目标 (12个月以上)**:
- 打造完整的视频处理工具链
- 支持分布式视频编码集群
- 建设活跃的开发者社区
- 成为跨领域工具产品的标杆

### 1.4 实施策略

采用**渐进式融合**方案,分 5 个阶段逐步实施:

| 阶段 | 时间 | 核心功能 | 目标 |
|------|------|---------|------|
| **阶段 1** | 2-3周 | FFmpeg 参数生成器 | 实现基础视频转码能力,验证市场需求 |
| **阶段 2** | 1周 | 进度解析器 | 实时进度显示,提升用户体验 |
| **阶段 3** | 1-2周 | 预设系统 | 预设管理、3FUI 格式互转 |
| **阶段 4** | 2-3周 | 高级功能 | 滤镜、色彩管理、剪辑区间 |
| **阶段 5** | 1-2周 | 优化完善 | 性能优化、用户体验提升 |

### 2.2 用户场景

#### 场景 1: 日常视频压缩

5. 点击"开始转码"
6. 查看实时进度条和预计剩余时间
7. 转码完成后,打开输出目录查看文件

**预期结果**: 视频成功压缩到 1080p,画质良好,文件大小适中

---

#### 场景 2: 批量格式转换

**用户**: 李四,DevOps 工程师

1. 选择 50 个 MOV 视频文件批量添加
2. 选择"批量 MP4 转换"预设模板
3. 设置并发数量为 3(充分利用 CPU)
4. 点击"开始批量处理"
5. 查看任务队列,看到 3 个任务同时运行
6. 中途暂停任务,调整参数后恢复
7. 所有任务完成后,检查输出文件

**预期结果**: 50 个视频全部转换为 MP4 格式,耗时约 3 小时

---

#### 场景 3: 高级视频压制

**用户**: 王五,视频专业工作者  
**背景**: 压制组工作,需要对一部电影进行高质量的压制

**操作流程**:
1. 导入 3FUI 中的高质量压制预设
2. 查看并调整参数(使用 libx265, CRF 20, 预设 medium)
3. 添加降噪滤镜(nlmeans, 强度 5)
4. 添加锐化滤镜(unsharp, 强度 1.5)
5. 设置二遍编码以提升质量
6. 开始压制,监控实时进度和码率
7. 压制完成后,使用 FFplay 验证效果

**预期结果**: 视频质量良好,文件大小符合预期

## 三、功能需求规格说明

### 3.1 阶段 1 (MVP): FFmpeg 参数生成器

#### 3.1.1 功能概述

实现基础的 FFmpeg 参数生成器,支持视频/音频编码参数配置,提供命令行预览功能。

#### 3.1.2 功能详情

##### F1.1 输出配置

**优先级**: P0  
**用户故事**: 故事 1

**功能描述**:
用户可以选择输出容器格式、配置文件命名规则。

**交互规格**:
1. 容器选择下拉框,支持以下选项:
   - MP4 (默认)
   - MKV
   - AVI
   - MOV
   - WebM
   - FLV
2. 命名规则配置:
   - 使用自动命名 (默认选中)
   - 前缀输入框
   - 后缀输入框
   - 自定义命名模式 (高级功能,隐藏)

**验收标准**:
- [ ] 用户可以选择不同的输出容器
- [ ] 容器选择后,支持的编码器列表自动更新
- [ ] 自动命名规则正确应用
- [ ] 输出路径正确生成

**数据模型**:
```typescript
interface OutputConfig {
  container: string;
  naming: {
    useAutoNaming: boolean;
    autoNamingOption: number;
    prefix: string;
    suffix: string;
    customPattern: string;
  };
  location?: string;
}
```

---

##### F1.2 视频编码器配置

**优先级**: P0  
**用户故事**: 故事 1

**功能描述**:
用户可以选择视频编码器、编码预设、质量控制等参数。

**交互规格**:
1. 编码器选择下拉框:
   - 编码器类别: H.264、H.265、VP9、AV1、Copy
   - 具体编码器: libx264、libx265、libvpx-vp9、libaom-av1
2. 编码预设下拉框 (ultrafast ~ veryslow)
3. 质量控制:
   - 控制模式: CRF (默认)、VBR、CBR
   - 质量值输入框 (CRF: 0-51, 默认 23)
   - 目标码率输入框 (VBR/CBR 模式, 例如: 5M)

**验收标准**:
- [ ] 编码器选择正确
- [ ] 预设选择正确
- [ ] 质量控制参数正确生成命令行
- [ ] 参数范围验证 (CRF 0-51)
- [ ] 命令行预览正确显示

**数据模型**:
```typescript
interface VideoConfig {
  enabled: boolean;
  encoderCategory: string;
  encoder: string;
  preset: string;
  profile: string;
  level: string;
  tune: string;
  passMode: number;
  passLogFile?: string;
}
```

- [ ] 音频编码器选择正确

- [ ] 声道数参数正确生成
- [ ] 命令行预览正确显示

**数据模型**:
```typescript
interface AudioConfig {
  enabled: boolean;

  bitrate: string;

  sampleRate: string;
  codec?: string;
}
```

### 3.2 阶段 2: 进度解析器
